# План реализации шифрования сообщений

## 🔐 КОНЦЕПЦИЯ ШИФРОВАНИЯ

### Архитектура ключей:
1. **MetaMask SEED** - для подписи транзакций (уже есть)
2. **Messenger SEED** - для дешифровки сообщений (новый ключ)
3. **Публичный ключ** - для шифровки, хранится в контракте

### Поток работы:
1. Пользователь генерирует пару ключей из Messenger SEED
2. Публичный ключ отправляется в контракт через registerPublicKey()
3. При отправке сообщения:
   - Сообщение шифруется публичным ключом получателя
   - Зашифрованное сообщение отправляется в контракт
4. При получении сообщения:
   - Зашифрованное сообщение извлекается из контракта
   - Дешифруется приватным ключом из Messenger SEED

## 🛠️ ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ

### 1. Алгоритм шифрования
- **Рекомендация**: ECIES (Elliptic Curve Integrated Encryption Scheme)
- **Кривые**: secp256k1 (совместимость с Ethereum)
- **Важно**: ECIES выполняется ТОЛЬКО на стороне клиента, НЕ в смарт-контракте
- **Библиотеки**: 
  - JavaScript: `crypto-js` + `@noble/secp256k1` + `@noble/ciphers`
  - Смарт-контракт: только хранение публичных ключей

### 2. Генерация ключей
```javascript
// Генерация пары ключей из SEED
const seed = "your messenger seed phrase here";
const privateKey = derivePrivateKeyFromSeed(seed);
const publicKey = derivePublicKeyFromPrivateKey(privateKey);
```

### 3. Шифрование сообщения
```javascript
// Шифрование сообщения публичным ключом получателя
const message = "Hello, this is a secret message";
const recipientPublicKey = getPublicKeyFromContract(recipientAddress);
const encryptedMessage = encryptMessage(message, recipientPublicKey);
```

### 4. Дешифрование сообщения
```javascript
// Дешифрование сообщения приватным ключом
const encryptedMessage = getMessageFromContract(messageId);
const decryptedMessage = decryptMessage(encryptedMessage, myPrivateKey);
```
