# Децентрализованная система загрузки событий для V2 версии

## 🌐 Обзор

CryptoMessenger использует **оптимизированную** децентрализованную систему загрузки событий с RPC фильтрацией для получения сообщений из блокчейна без централизованного бэкенда.

## 🚀 Ключевые оптимизации

### RPC Фильтрация (вместо клиентской фильтрации)
- **Было**: Загружаем ВСЕ события → фильтруем на клиенте
- **Стало**: Фильтруем на RPC сервере → получаем только нужные события
- **Результат**: Экономия трафика в 100-1000 раз!

### Умный диапазон блоков
- **Первый запуск**: Последние 1000 блоков (2-3 часа истории)
- **Последующие**: С последнего блока + 1 до 'latest'
- **Результат**: Быстрая загрузка только новых сообщений

## 🏗️ Архитектура

### Hybrid RPC + Smart Caching
Оптимизированный подход, объединяющий:
- **RPC фильтрация** на уровне сервера
- **Умное кэширование** последних блоков
- **Множественные RPC endpoints** для надежности
- **Offline поддержка** через IndexedDB

### Компоненты системы

#### DecentralizedEventSystem (оптимизированная версия)
```javascript
class DecentralizedEventSystem {
    constructor(contract = null) {
        this.rpcEndpoints = [
            'https://base-rpc.publicnode.com',
            'https://mainnet.base.org',
            'https://base.drpc.org'
        ];
        this.contract = contract; // Web3 контракт для оптимизированных запросов
        this.memoryCache = new Map();
        this.lastMessageBlocks = new Map(); // Кэш последних блоков
        this.isOnline = navigator.onLine;
    }
}
```

#### 🎯 Оптимизированная загрузка сообщений
```javascript
async loadMessagesForUsers(user1, user2, options = {}) {
    // 1. Определяем оптимальный диапазон блоков
    const range = await this.getOptimalBlockRange(user1, user2);
    
    // 2. Загружаем ТОЛЬКО нужные события через RPC фильтрацию
    const events = await this.contract.getPastEvents('MessageSent', {
        filter: {
            senderAddress: [user1, user2],      // Фильтр на сервере!
            recipientAddress: [user1, user2]    // Только нужные сообщения
        },
        fromBlock: range.fromBlock,
        toBlock: range.toBlock
    });
    
    return events;
}
```

## 🧠 Умное определение диапазона блоков

### Стратегия блоков:
```javascript
async getOptimalBlockRange(user1, user2) {
    // 1. Получаем последний блок для каждого пользователя
    const lastBlock1 = await this.getLastMessageBlock(user1);
    const lastBlock2 = await this.getLastMessageBlock(user2);
    const lastBlock = Math.max(lastBlock1 || 0, lastBlock2 || 0);

    // 2. Первый запуск - последние 1000 блоков
    if (!lastBlock) {
        const currentBlock = await this.getCurrentBlock();
        return {
            fromBlock: Math.max(0, currentBlock - 1000),
            toBlock: currentBlock,
            isInitial: true
        };
    }

    // 3. Последующие - с последнего блока + 1
    return {
        fromBlock: lastBlock + 1,
        toBlock: 'latest',
        isInitial: false
    };
}
```

### Преимущества:
- **Быстрая загрузка**: Только новые сообщения
- **Экономия трафика**: Не загружаем историю повторно
- **Адаптивность**: Автоматически определяет нужный диапазон
