### 🚨 ПРИНЦИП:
Model-View-Controller.
Сначала всегда обновляем данные.
А уж потом на основании данных отрисовываются изменённые компоненты.

### 🚨 ОПРЕДЕЛЕНИЯ:
В контексте одного авторизованного в приложении пользователя,
* У нас каждому Контакту соответствует один и только один чат.

### 🚨 СЛУЖЕБНЫЕ ФУНКЦИИ:
* У нас должна быть функция которая быстро по ContactAddress, возвращает ChatID
* У нас должна быть функция которая быстро по ChatID, возвращает ContactAddress
Только не делать это циклами! Лучше создай mapping. Не забывай обновлять его при появлении новых контактов-чатов.

### 🚨 НАЧАЛЬНОЕ СОСТОЯНИЕ:

1. Инициации данных быть не должно. Всё решается алгоритмом описанным ниже.
   Изначально списки контактов и сообщений пустые.
   contactLastIndex=0
   messLastIndex=0

### 🚨 АЛГОРИТМ ЗАГРУЗКИ ДАННЫХ:

2. Каждые 15 секунд polling проверяет наличие новых сообщений.
   startIndex=messLastIndex+1
   endIndex=startIndex-1+100    (сохранить 100 как константу в config.js)
   const newMessages = await contract.methods.getMessagesPaginated(startIndex, endIndex);
3. Создаём множество, извлекая chatID из новых полученных сообщений
4. Проверяем, есть ли среди этого множества chatID неизвестные чаты
   Получаем bool isExistsNewChatIDs
5. Если isExistsNewChatIDs==false, то переходим к пункту 7, иначе к пункту 6.
6. Пытаемся загрузить очередные контакты
   startIndex=contactLastIndex+1
   endIndex=startIndex-1+100    (сохранить 100 как константу в config.js)
   const newContacts = await contract.methods.getContactsPaginated(startIndex, endIndex);
   Сохраняем новые контакты-чаты в памяти (маппинги).
    (не в интерфейсе, а в данных).
   После этого ВЫХОДИМ из этого алгоритма!
7. Сохраняем новые сообщения в памяти (не в интерфейсе, а в данных).
   При сохранении каждого из сообщений, последовательно (по одному): 
     7.1. обновляем данные по контактам-чатам (поля: последнее сообщение, датавремя последнего сообщения, статус чата, ...)
8. Если количество новых сообщений > 0, то
   вызываем отдельную функцию пересортировки всех контактов, которая сортирует по принципу:
   * Сначала чаты со статусом **waitingAcceptanceFromMe** (входящие приглашения)
     Внутри этой группы сортировка: **старые сообщения выше** (по возрастанию времени)
   * Потом чаты со статусом **allowedWrite** (активные чаты)
     Сортировка: **новые сообщения выше** (по убыванию времени)
   * Потом чаты со статусом **waitingAcceptanceFromOther** (исходящие приглашения)
     Сортировка: **старые сообщения выше** (по возрастанию времени)
   * Потом чаты со статусом **notAllowedWrite** (заблокированные чаты)
     Сортировка: **новые сообщения выше** (по убыванию времени)
9. Конец алгоритма

Эта попытка получения новых данных повторится через 15 секунд.
