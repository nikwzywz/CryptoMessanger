# Архитектурные решения CryptoMessanger

## Основные принципы
- **ДЕЦЕНТРАЛИЗОВАННЫЙ мессенджер** - главное требование
- Никаких централизованных серверов или доверенных посредников
- Все сообщения хранятся в блокчейне Base

## Хранение сообщений
- **Комбинированный подход:** Events для сообщений + State для метаданных
- Events могут содержать сообщения до 30KB с Unicode и эмодзи
- **Сжатие gzip** только для сообщений длиннее определенного порога (избежать накладных расходов на короткие сообщения)

## Безопасность и шифрование
- **End-to-end шифрование** на стороне клиента
- **Обмен публичными ключами** через смарт-контракт
- Публичные ключи хранятся в блокчейне (открыто)
- Адрес кошелька ≠ публичный ключ

## Защита от спама
- **Белый список** вместо черного (спам-адреса создаются бесплатно)
- Естественная защита через стоимость газа
- Пользователи добавляют контакты в белый список

## UX и транзакции
- **НЕТ session keys** - нарушает децентрализованность
- Каждое сообщение = отдельная транзакция
- Пользователь подтверждает каждую отправку через MetaMask/Rabby

## Индексация и уведомления
- **НЕТ The Graph** - слишком громоздко для клиента
- Простая подписка на Events через Web3.js
- Индексация на стороне клиентского приложения

## Технический стек
- **Frontend:** React/Vue + Web3.js
- **Blockchain:** Base Network (дешевые транзакции)
- **Smart Contract:** Solidity
- **Шифрование:** Web Crypto API (браузер) или crypto-js

## Детальные решения

### Сжатие сообщений
- **Порог gzip:** 500 байт
- Сообщения короче 500 байт сжимать не нужно

### Механизм белого списка
- **Запрос на добавление в контакты:** Пользователь А вызывает метод "прошу добавить меня в ваши контакты"
- **Первое сообщение:** Можно приложить одно сообщение к запросу
- **Дополнительная плата:** ~$10 в ETH в пользу получателя (настраивается владельцем кошелька)
- **Принятие:** Получатель оценивает, спам ли это
- **Возврат средств:** При принятии запроса ETH возвращается отправителю
- **Реализация:** mapping[address получателя][address отправителя] => boolean

### Технические решения
- **Групповые чаты:** Записать на "подумать потом" (не в MVP)
- **Потеря ключей:** Ничего не делать (как с потерей SEED фразы)
- **Приложение:** PWA для уведомлений в любом случае
- **Локальное хранение:** Все сообщения хранить локально до очистки пользователем
- **Мультиаккаунт:** Поддерживается через Rabby Wallet автоматически
- **Валидация:** Не требуется
- **Rate limiting:** После MVP (записать на "потом")
- **Экспорт истории:** После MVP (записать на "потом")
