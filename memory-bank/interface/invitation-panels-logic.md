# Логика работы интерфейса приложения CryptoMessenger

## Обзор системы панелей

Интерфейс CryptoMessenger динамически изменяется в зависимости от статуса чата между пользователями. Вместо статичного поля ввода сообщений используется система адаптивных панелей.

## Состояния интерфейса

### 1. АКТИВНЫЙ ЧАТ
**Условие:** `chat.isActive = true`

**Интерфейс:**
- ✅ Показывается поле "Введите сообщение..."
- ✅ Кнопка отправки активна
- ✅ Пользователь может свободно писать сообщения

**Код:**
```javascript
showNormalInputArea();
```

### 2. ВХОДЯЩЕЕ ПРИГЛАШЕНИЕ
**Условие:** `chat.isActive = false && chat.isNeedAcceptance = true && chat.inviter !== currentUser`

**Интерфейс:**
- 📨 Панель "Приглашение в контакты"
- ✅ Кнопка "Разрешить общение" (зелёная)
- ❌ Кнопка "Запретить" (красная)
- 📍 Адрес отправителя: "От: 0x..."
- 💬 Расшифрованное сообщение приглашения
- 🚫 Поле ввода сообщений СКРЫТО

**Код:**
```javascript
showInvitationPanel(contactAddress, contactName, introMessage);
```

### 3. ИСХОДЯЩЕЕ ПРИГЛАШЕНИЕ
**Условие:** `chat.isActive = false && chat.isNeedAcceptance = true && chat.inviter === currentUser`

**Интерфейс:**
- ⏳ Панель "Ожидание принятия приглашения"
- 🔄 Анимированная иконка ожидания (пульсирует)
- 📍 Адрес получателя: "Кому: 0x..."
- 💬 Сообщение "Пользователь ещё не ответил на ваше приглашение"
- 🚫 Поле ввода сообщений СКРЫТО

**Код:**
```javascript
showWaitingPanel(contactAddress, contactName);
```

### 4. НЕАКТИВНЫЙ ЧАТ БЕЗ ПРИГЛАШЕНИЯ
**Условие:** `chat.isActive = false && chat.isNeedAcceptance = false`

**Интерфейс:**
- 📝 Панель "Отправить приглашение"
- 📤 Кнопка "Отправить приглашение" (синяя)
- 📍 Адрес получателя: "Кому: 0x..."
- 💬 Сообщение "Этот пользователь не в ваших контактах"
- 🚫 Поле ввода сообщений СКРЫТО

**Код:**
```javascript
showCreateInvitationArea(contactAddress, contactName);
```

## Алгоритм определения состояния

```javascript
async function checkChatStatusAndShowPanel(contactAddress, contactName) {
    // 1. Получаем chatId
    const chatId = await contract.methods.getChatId(currentUser, contactAddress).call();
    
    // 2. Получаем информацию о чате
    const chat = await contract.methods.getChat(chatId).call();
    
    // 3. Проверяем статус
    if (chat.isActive) {
        // Обычный чат → показываем поле ввода
        showNormalInputArea();
    } else {
        if (chat.isNeedAcceptance) {
            if (chat.inviter === currentUser) {
                // Мы отправители → показываем панель ожидания
                showWaitingPanel();
            } else {
                // Мы получатели → показываем панель принятия
                showInvitationPanel();
            }
        } else {
            // Чат НЕ активен и НЕТ приглашения
            // Показываем область для создания приглашения
            showCreateInvitationArea();
        }
    }
}
```

## Структура данных смарт-контракта

```solidity
struct Chat {
    uint256 messageCount;
    ChatMessage[] messages;
    bool isActive;           // true = чат активен, можно писать
    bool isNeedAcceptance;   // true = ожидает принятия приглашения
    uint256 createdAt;
    address inviter;         // Кто отправил приглашение
    uint256 invitationFee;
}
```

## Методы смарт-контракта

- `getChatId(user1, user2)` → получить ID чата
- `getChat(chatId)` → получить полную информацию о чате
- `invitationSend()` → отправить приглашение
- `invitationAccept()` → принять приглашение
- `invitationReject()` → отклонить приглашение

## Визуальные индикаторы в списке контактов

**Входящее приглашение:**
- 🟢 Зелёная полоска слева (`incoming-request`)
- ❗ Красный бейдж "!" (`contact-badge single-digit`)

**Исходящее приглашение:**
- 🟡 Жёлтая полоска слева (`outgoing-request`)
- Текст "Приглашение отправлено"

**Обычный контакт:**
- Без полосок
- Бейдж с количеством непрочитанных (если есть)

## Принципы UX

1. **Блокировка общения** до принятия приглашения
2. **Одна панель в один момент времени** - нет дублирования интерфейса
3. **Понятные действия** - кнопки соответствуют возможным действиям
4. **Контекстная информация** - показываем адреса и сообщения
5. **Адаптивность** - корректное отображение на мобильных устройствах

## Мобильная адаптивность

На экранах шириной ≤768px:
- Кнопки располагаются вертикально
- Уменьшенные отступы и размеры иконок
- Панели занимают всю ширину экрана
- Поддержка системной кнопки "назад" Android
